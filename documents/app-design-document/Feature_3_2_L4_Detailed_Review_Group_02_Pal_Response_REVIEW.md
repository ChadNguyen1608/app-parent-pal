## L4 remediation — FR-02 · Web knowledge fallback contract (author verification only)

This clause implements the approved knowledge-map [§1.1](../knowledge/spec-ban-do-kien-thuc.md) and extends prior D02-T02. **It does not permit unrestricted web browsing or use of a model merely because the internal KB lacks data.** First establish applicable user/content category, source and processing eligibility (including OD-05), then evaluate internal sufficiency. When a **permitted** external search is needed:
1. For a parent-facing external lookup, **notify the parent before search** that Parent-Pal's vetted reference KB lacks the requested information. If advance notice/eligible request cannot be established, do not search.
2. Cite the source **for each web-derived claim** and mark each web-derived claim **"chưa kiểm chứng"**. No promotion of external data to verified or approved knowledge by caching, paraphrase, model synthesis or user display; if provenance/claim-level labeling cannot be preserved, abstain.
3. Create **one minimal verification-queue record per lookup**, with anonymized question, claims shown, source references and outstanding official-source/expert verification steps. Never include raw Journal or restricted identity/context; queued result is not approval.
4. **Exclude** diagnosis, prescriptions, drugs/doses and urgent/emergency cases from web fallback. Route only through separately approved static response/appropriate professional-help policy, with current lawful processing gates. The fixed exception does not authorize AI-created medical advice.
5. An external LLM-only route that cannot provide a valid auditable source does **not** make factual claims sourced from the web; unsupported claims are withheld or explicitly out-of-scope under the approved capability. Education/training category source routing remains the current authorized scope. Other task classes require separate sourcing authorization.
